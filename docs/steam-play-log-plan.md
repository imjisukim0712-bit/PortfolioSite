# 스팀 연동 게임기록 · 장르 방사형 그래프 — 계획서

> 상태: **계획만 세운 단계. 아직 아무것도 구현하지 않았습니다.**
> 목표: 스팀에서 플레이 기록을 자동으로 가져와 장르별로 묶고, 게임기록(`play.html`) 맨 위에
> 주요 장르 5~7개짜리 방사형(레이더) 그래프를 띄운다.

---

## 0. 한 줄 답

**됩니다. 다만 브라우저에서 스팀을 직접 부르는 방식은 불가능하고, "정해진 시각에 GitHub Actions 가
대신 불러와 JSON 파일로 저장해 두는" 방식이라야 합니다.** 이 사이트는 빌드 도구·서버 없는 정적
사이트(GitHub Pages)라서, 스팀 호출은 사이트 밖(깃허브 서버)에서 미리 끝내 두고 화면은 그 결과
파일만 읽습니다. 작업량은 대략 **하루** 정도입니다.

## 1. 왜 브라우저에서 바로 못 부르나 (직접 확인한 사실)

| 막는 것 | 내용 |
|---|---|
| **API 키가 비밀** | `api.steampowered.com` 호출에는 개인 API 키가 필요합니다. 정적 사이트의 JS 에 키를 넣으면 소스가 그대로 공개되어 누구나 내 키로 호출할 수 있습니다. |
| **CORS 차단** | `api.steampowered.com` · `store.steampowered.com` 둘 다 응답에 `Access-Control-Allow-Origin` 헤더가 없습니다(2026-09 확인). 브라우저에서 `fetch` 하면 키가 맞아도 차단됩니다. |

→ 그래서 **호출은 깃허브 액션(서버 쪽)에서, 화면은 저장된 JSON 만** 읽는 구조가 유일하게 깔끔합니다.
(프록시 서버를 따로 띄우는 방법도 있지만, 서버를 하나 더 관리해야 하므로 이 사이트에는 과합니다.)

## 2. 준비물 (사람이 직접 해야 하는 것)

1. **SteamID64** — 17자리 숫자. 프로필 주소가 `/id/닉네임` 형태면 `ISteamUser/ResolveVanityURL` 로 변환하거나 프로필에서 확인합니다.
2. **스팀 웹 API 키** — <https://steamcommunity.com/dev/apikey> 에서 발급. 계정이 '제한 계정'이 아니어야 하고(스팀에서 $5 이상 결제 이력 필요), 이메일 인증이 되어 있어야 합니다.
3. **프로필 공개 설정** — 스팀 프로필 → 개인정보 설정에서 **프로필**과 **게임 상세 정보**를 '공개'로. 비공개면 소유 게임 목록이 빈 값으로 돌아옵니다.
4. **깃허브 시크릿 등록** — 저장소 Settings → Secrets → Actions 에 `STEAM_API_KEY`, `STEAM_ID` 두 개. 키는 저장소에도 사이트에도 절대 커밋하지 않습니다.

## 3. 데이터 흐름

```
[GitHub Actions · 주 1회 + 수동 실행]
   1) IPlayerService/GetOwnedGames      → 소유 게임 + 총 플레이 시간(분)
   2) store appdetails (새 게임만)       → 게임별 장르 (캐시에 쌓아 둠)
   3) 집계 · 정리
        ↓  커밋
assets/play-steam.json        ← 화면이 읽는 결과물 (집계된 숫자만)
assets/steam-cache.json       ← appid → 장르 캐시 (호출 수를 줄이려고 보관)
        ↓
[사이트] render.js 의 renderPlay() 가 JSON 을 읽어 방사형 그래프 + 요약을 그림
```

## 4. 쓰는 API

| 무엇 | 주소 | 주는 것 | 비고 |
|---|---|---|---|
| 소유 게임·플레이 시간 | `api.steampowered.com/IPlayerService/GetOwnedGames/v1/?key=&steamid=&include_appinfo=1&include_played_free_games=1` | `appid` · `name` · `playtime_forever`(분) · `img_icon_url` · `rtime_last_played` | 내 키 + 내 SteamID 라서 마지막 플레이 시각까지 옵니다 |
| 최근 2주 | `IPlayerService/GetRecentlyPlayedGames/v1/` | 최근 플레이 게임 · `playtime_2weeks` | '요즘 하는 게임' 줄에 쓰면 좋습니다 |
| 프로필 | `ISteamUser/GetPlayerSummaries/v2/` | 닉네임 · 아바타 | 선택 |
| 게임별 장르 | `store.steampowered.com/api/appdetails?appids=<id>&l=korean&filters=basic,genres` | `genres[{id,description}]` · `categories` | **비공식 API · 약 5분에 200회 제한** → 캐시 필수. `filters` 로 응답을 확 줄일 수 있습니다 |

장르를 더 잘게(로그라이크·소울라이크 같은 유저 태그) 나누고 싶으면 SteamSpy(`steamspy.com/api.php?request=appdetails&appid=`)를 곁들일 수 있습니다. 역시 비공식이고 초당 1회 제한이라 캐시 전제입니다.

## 5. 장르 집계 규칙 (정하고 가야 할 부분)

- **키는 스팀 장르 id 로, 이름은 우리가 가진다.** `l=korean` 으로 받은 한국어 설명을 그대로 쓰지 않고
  `1=액션 / 2=전략 / 3=RPG / 25=어드벤처 / 28=시뮬레이션 / 29=MMO / 9=레이싱 / 18=스포츠 …` 처럼
  `content.js` 에 `{ ko, en }` 이름표를 둡니다 (사이트 이중언어 규칙과 맞물립니다).
  실제 응답으로 확인한 예(2026-09): 스텔라리스 `[28 시뮬레이션, 2 전략]` · 하데스 `[1 액션, 23 인디, 3 RPG]` ·
  도타2 `[1 액션, 2 전략, 37 무료 플레이]` · 사이버펑크2077 `[3 RPG]`.
- **장르가 아닌 태그는 뺍니다** — `인디(23)` · `앞서 해보기(70)` · `무료 플레이(37)` · `캐주얼(4)`은
  장르라기보다 판매 형태라서 축으로 세우면 그래프가 무너집니다 (제외 목록으로 관리).
- **한 게임이 여러 장르일 때**: 플레이 시간을 장르 수로 나눠 배분합니다(합계가 총 시간과 맞아떨어짐).
  "첫 장르만 인정" 방식은 단순하지만 전략+시뮬 같은 조합을 놓칩니다.
- **자를 기준**: 30분 미만 플레이한 게임은 빼면 그래프가 훨씬 정직해집니다 (라이브러리에 쌓아만 둔 게임 제거).
- **손으로 고칠 구멍**: 스팀 장르가 실제와 다른 경우가 있어(예: 대작 인디), `content.js` 에
  `play.steam.override: { "<appid>": ["전략","시뮬레이션"] }` 같은 보정 칸을 둡니다.

## 6. 방사형 그래프 설계

- **축 5~7개** — 시간이 많은 장르 순으로 6개를 기본값으로, 나머지는 '그 외'로 묶어 그래프 밖 숫자로만 표시.
- **무엇을 그릴까** — 요청대로 "장르별 몇 개를 했는가"(게임 수)와 "얼마나 오래 했는가"(시간)는 다른 그림입니다.
  → **시간 기준 다각형 하나 + 축 이름 옆에 `42시간 · 7종` 병기**를 권합니다. 두 다각형을 겹쳐 그리면
  스킨(픽셀·브루탈 등)에서 색이 부족해 읽기 어려워집니다.
- **눈금** — 한 장르(예: 스텔라리스 1,000시간)가 압도적이면 나머지가 점처럼 눌립니다.
  값은 최대값 대비 비율로 두되 **제곱근 눈금**을 써서 형태가 살아나게 하고, 실제 숫자는 축 라벨에 적습니다.
- **구현** — 차트 라이브러리 없이 **손으로 그린 SVG**(약 60줄). 이 저장소가 이미 카드 아트·고스트를
  SVG 로 직접 그리고 있고, 색·선 굵기를 스킨 토큰(`--accent` · `--ink` · `--bw`)에 맡길 수 있어
  테마 7종에 그대로 얹힙니다. 픽셀 테마에서는 `shape-rendering: crispEdges` 만 더하면 됩니다.
- **접근성** — 그래프 옆(또는 아래)에 같은 내용을 `<table>`(또는 정의 목록)로 함께 두고,
  SVG 에는 `role="img"` + `aria-label="장르별 플레이 시간: 전략 1,830시간 …"`. 모션 최소화 설정에서는 등장 애니메이션 생략.
- **자리** — `render.js` 의 `renderPlay()` 맨 위, 기존 `section__head` 바로 아래에 새 블록
  `.play-radar`(그래프 + 요약 수치 3개: 총 플레이 시간 · 게임 수 · 최근 플레이). 지금 손으로 쓴
  `play.cards` 는 그 아래 그대로 둡니다 — 자동 수치가 위, 직접 쓴 해설이 아래인 구성입니다.

## 7. 단계별 작업

| 단계 | 내용 | 대략 |
|---|---|---|
| 1 | `tools/steam-sync.mjs` — 스팀 호출 · 캐시 · 집계 · `assets/play-steam.json` 쓰기 (의존성 없는 순수 Node) | 3h |
| 2 | `.github/workflows/steam-sync.yml` — 주 1회(월 03:00 KST) + 수동 실행, 변경 있을 때만 커밋 | 1h |
| 3 | `render.js` 에 방사형 SVG + 요약 블록, `style.css` 에 기본 스타일 | 3h |
| 4 | 테마 7종 확인 · 이중언어 이름표 · 접근성 표 · 모바일 확인 | 2h |

## 8. 미리 알아 둘 함정

- **깃허브 액션이 스스로 커밋하면 Pages 배포가 안 걸립니다.** 기본 `GITHUB_TOKEN` 으로 push 한
  커밋은 다른 워크플로를 깨우지 않습니다. → 동기화 워크플로 안에서 **배포 스텝까지 이어서** 하거나,
  `deploy-pages.yml` 을 `workflow_call` 로 바꿔 불러야 합니다.
- **appdetails 호출 제한(5분에 200회)** — 첫 실행에서 게임이 300개면 한 번에 다 못 가져옵니다.
  캐시에 없는 것만 1.5초 간격으로, 한 번에 최대 150개씩 나눠 받는 식으로 짭니다.
- **공개 범위** — 만들어진 JSON 은 사이트에 그대로 공개됩니다. 소유 게임 전체 목록을 공개하고 싶지
  않다면 **집계 숫자 + 상위 10개만** 저장하도록 스크립트에서 잘라 냅니다 (권장).
- **스팀 밖 기록은 안 잡힙니다** — 모바일·콘솔·스팀 미등록 게임(지금 카드의 러스티레이크 모바일 등)은
  손으로 쓴 카드로 남습니다. 그래프 제목을 '스팀 기준'이라고 밝혀 두는 편이 정직합니다.
- **플레이 시간은 '누적'만 옵니다** — 연도별 추이 같은 건 스팀이 주지 않습니다. 추이를 원하면
  매 실행 결과를 `assets/steam-history.json` 에 한 줄씩 쌓아 두는 방식이라야 합니다(원하면 1단계에 포함).
- **이름 노출** — 스팀 닉네임·아바타는 넣지 않아도 됩니다. 숫자만으로도 그래프는 완성됩니다.

## 9. 물어볼 것 (정해 주시면 그대로 만듭니다)

1. 그래프 값은 **플레이 시간** 기준으로 갈까요, **게임 수** 기준으로 갈까요? (권장: 시간, 게임 수는 라벨에 병기)
2. 소유 게임 **전체 목록을 공개**해도 괜찮은가요, 아니면 **집계 + 상위 10개만** 공개할까요? (권장: 후자)
3. 갱신 주기 — 주 1회면 충분할까요? (하루 1회도 부담은 없습니다)
4. 스팀 닉네임·아바타를 화면에 넣을까요?
5. 장르는 스팀 공식 장르(굵직한 분류)로 충분한가요, 유저 태그(로그라이크·소울라이크 같은 세부)까지 볼까요?
   후자면 SteamSpy 를 하나 더 붙입니다.
