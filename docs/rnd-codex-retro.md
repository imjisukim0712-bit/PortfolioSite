# 패미컴 포트폴리오 — 새로운 시각 언어 R&D

조사·제작: 2026-10-27. Codex 가 독립 worktree 에서 진행(커밋·푸시·배포 없음). 브라우저 검증은 Codex 샌드박스에서 막혀 Claude 가 대신 찍어 2차 손질에 넘겼고, 병합 후 6개 페이지 × 라이트/다크 × 3폭 오류·넘침 없음을 확인함.

**2차 갱신:** 사용자가 실제 화면과 오류·넘침 0, 꽂기 → 개요 정상이라는 측정 결과를 제공했다. 이를 보고 CSS 우선순위·가독성·모바일·푸터를 수정했다. 아래 ‘미실행’ 기록은 이 환경에서 직접 실행한 브라우저 검사에 관한 것이며, 사용자가 제공한 검증과 구분한다. 변경 근거와 수정 후 확인 범위는 [ROUND2.md](ROUND2.md)에 정리했다.

## 결과와 확인 상태

| 실제 구현 | 열어볼 주소 | 핵심 구조 |
|---|---|---|
| 기념 선집 / Laureate | `index.html?skin=pixel-fc-laureate` | 진홍 단색장 + 월계 메달 + 세리프 + 가는 이중 금속선 |
| 소장품 전시 / Gallery | `index.html?skin=pixel-fc-gallery` | 거대한 원형 전시벽 + 가벼운 산세리프 + 원형 번호 + 라벨·받침대 |
| 랠리 프린트 / Rally Print | `index.html?skin=pixel-fc-rally` | 비대칭 사선 띠 + 기울임꼴 + 면취한 기기 + 굵은 정보 띠 |

**브라우저 검증은 미실행이다.** `python3 -m http.server 8901`은 소켓 생성 시 `PermissionError: [Errno 1] Operation not permitted`로 종료했다. 지정한 `chromium.launch()`도 `sandbox_host_linux.cc:41`의 `shutdown: Operation not permitted`로 종료했다. 권한 우회나 별도 배포로 대체하지 않았다. 원본 에러와 0건 촬영 상태는 [shots/validation.json](../tools/)에 있다.

갤러리 JPG 3장은 **1280×800 SVG 구성 연구를 800×500으로 축소한 임시 이미지**다. 그림 안에 촬영 대기라고 표시했다. 실제 사이트 캡처가 아니며, 웹폰트·원근 투영·실제 카드 아트·내용의 자동 줄바꿈과 차이가 있다. SVG 몸통의 실루엣·외곽선·두께는 실제 JS가 생성하는 것과 같다. 이 SVG와 구성 이미지는 직접 렌더해 육안 확인했다. 실제 브라우저 스크린샷을 확인한 것으로 주장하지 않는다.

## 1. 실제 조사: 출처와 추출한 시각 언어

방법: 웹 검색, 공식 URL 열람, 이미지 검색으로 보존된 화면·인쇄물 확인, 공식 설명서 PDF와 이미지 대체텍스트 확인. 아래의 **관찰**은 접근 가능한 문서·이미지의 정보이며 **적용**은 이 포트폴리오를 위한 해석이다. 웹사이트 모션은 브라우저가 차단되어 재생·타이밍을 실측하지 못했다. 아래 모션 제안은 레퍼런스의 실제 동작에 대한 단정이 아니다.

### A. 닌텐도 공식 웹과 전시·매장

1. **일본 공식 홈페이지**
   - 출처: https://www.nintendo.co.jp/ → https://www.nintendo.com/jp/index.html
   - 관찰: TOPICS / PICKUP / SOFTWARE / WHAT'S NEW처럼 정보의 성격을 제목으로 명시한다. 크고 작은 콘텐츠 모듈을 반복하는 체계다. 옛 `.co.jp` 경로는 현재 `.com/jp`로 이동한다.
   - 추출: 게임 감성을 모든 문장에 장식하는 대신, 제목·콘텐츠·보조 정보의 위계를 일관되게 둔다. 카드와 프로젝트 본문에도 같은 계층을 쓴다.

2. **미국 공식 홈페이지**
   - 출처: https://www.nintendo.com/us/
   - 관찰: 상단 Explore / Shop / Support, 프로모션 슬라이드, Featured, Gaming systems, News로 이어진다. 이미지 중심 프로모션과 서비스 설명을 별도 모듈로 묶는다.
   - 추출: 한 장면에 모든 정보를 넣지 않는다. 첫 화면은 사람과 기기, 아래는 업무 기록으로 역할을 나눈다. 내비게이션은 읽기 쉬운 보통 산세리프로 유지한다.
   - 미확인: 슬라이드의 실제 전환 모션·인터벌.

3. **닌텐도 뮤지엄**
   - 출처: https://museum.nintendo.com/en/index.html
   - 전시: https://museum.nintendo.com/en/exhibition/index.html
   - 화면 보조: https://www.cinra.net/index.php/article/202408-whn-nintendo_edteam
   - 관찰: Learn / Interactive Exhibits / Make & Play의 큰 구분, 제품을 나란히 비교하는 전시, 예약 안내와 관람 안내의 명확한 분리. 공개된 화면에서는 회백색 건물·여백·차분한 정보 영역이 중심이다.
   - 추출: ‘옛 게임기를 전시하는 현대의 공간’이라는 시간차. 낡은 종이·픽셀 효과 없이도 물건의 역사성을 전달할 수 있다. Gallery의 원형 전시벽·번호·받침대는 여기서 확장한 **독자적 제안**이다. 실제 뮤지엄 사이트의 원형 배경을 복제한 것이 아니다.

4. **Nintendo TOKYO 등 공식 스토어**
   - 출처: https://www.nintendo.com/jp/officialstore/index.html
   - 원래 주소: https://www.nintendo.co.jp/officialstore/
   - 공식 상품 카탈로그 검색 결과: https://www.nintendo.com/jp/officialstore/pdf/202106_catalog.pdf
   - 카탈로그 표지 사진 보조: https://sapporolife.hateblo.jp/entry/2021/08/26/205602
   - 관찰: 도시별 반복되는 매장 정보와 상품 이미지, 주소·안내의 구조화. 2021 카탈로그 표지 사진은 빨간 큰 면 위에 간단한 흰 글자로 정리되어 있다.
   - 한계: 공식 PDF 본문은 19.6MB 크기 제한으로 열리지 않아 전체 지면을 읽었다고 주장하지 않는다.
   - 추출: 굿즈의 선물·소장 가치, 붉은 단색장과 짧은 라벨, 상품군 사이의 여백. 캐릭터나 로고를 제거한 뒤에도 남는 정돈 방식만 가져온다.

### B. 기념판과 숫자·로고 체계

5. **슈퍼 마리오 25주년 스페셜 팩**
   - 공식 제품: https://www.nintendo.co.jp/wii/svmj/index.html
   - 공식 관련 인터뷰: https://www.nintendo.co.jp/wii/interview/svmj/vol2/index.html
   - 패키지 사진 보조: https://www.nintendoworldreport.com/blog/24551/unboxing-the-super-mario-all-stars-limited-edition-set
   - 직접 제공된 근접 참고: 사용자 첨부 `ref-box.png`.
   - 관찰: 넓은 빨간 면, 제한된 금색 잉크, 대형 숫자와 월계관의 중심 정렬, 아래에 작은 상품 정보. 공식 페이지는 게임·히스토리 북·CD를 구분한다.

   - 적용: Laureate의 메달은 독자적으로 그린 일반 월계관·별·권호 `01`. `25`, `30`, 실제 기념 로고, 마리오, Wii 및 Nintendo 로고는 넣지 않는다. `01`은 경력 연수·수상·주년 수치를 뜻하지 않는다.

6. **마리오 30주년과 관련 상품**

   - 공식 30주년 amiibo 페이지: https://www.nintendo.co.jp/wiiu/amaj/products/amiibo.html

8. **패미컴 40주년 및 하드웨어 아카이브**

## 3. 구현과 범위

- 출발점은 요청한 `sed 's/pixel-fc-classic/<새 id>/g'`로 CSS·JS를 각각 복제했다. 이후 각 복제본에 독립된 전체 스타일과 SVG 생성 코드를 추가했다.
- 새 ID: `pixel-fc-laureate`, `pixel-fc-gallery`, `pixel-fc-rally`. `themes.js`에 한·영 이름/설명, swatch, scripts를 등록하고 `fc-stage.js`의 `SKINS`에 추가했다. 확정 테마는 바꾸지 않았다.
- 공용 파일 수정은 위 두 파일의 등록 부분뿐이다. `fc-body.js`, `render.js`, `main.js`, `style.css`, `content.js`, 기존 시안은 수정하지 않았다.
- 몸통은 각 시안 JS 안의 한 SVG다. viewBox `1000×500`, 앞면·연속 외곽선·아래로 20단위 이동한 동일 실루엣으로 두께를 그린다. 몸통 실루엣의 클립 안에서 손잡이·장식만 채운다. 분리된 CSS 상자 조각으로 외곽선을 만들지 않는다.
- 900px 이상에서 `.fcs-rig`가 크기 기준이다. 몸통 높이 `50cqw`, 손잡이 `13cqw`, 콘텐츠 화면 `x166–834 / y56–444`를 CSS의 `margin:5.6cqw 3.6cqw`와 일치시켰다. 기기와 진열판은 하나의 `.fcs-rig`로 함께 기울인다.
- 작은 화면은 원본의 세로 휴대기 배치를 유지한다. 320px에서는 버튼·패딩·사진 폭을 줄이고, 카드 내부 cqw 칸은 바꾸지 않는다. 가로 넘침이 없다는 실측 판정은 아직 없다.
- 1280×720의 예상 세로 점유를 계산해 낮은 화면에서 stage 상하 여백을 `22px / 26px`로 줄였다. 실제 웹폰트 적용 후 결과는 추가 확인이 필요하다.
- 사진의 픽셀·색·혼합·필터는 건드리지 않았다. 금속 액자·아치형 액자 등 바깥 프레임만 시안에 맞게 지정했다. SVG drop-shadow는 몸통 그림에만 적용된다.
- `.gcard`의 이름·메타·그림·개요 cqw 치수는 원본대로다. 안쪽 치수를 화면별 미디어 쿼리로 바꾸지 않는다. 카드 아트에는 일반 원형/아치/사선의 프레임만 적용한다.
- 도구 로고 판은 흰색 `!important`를 유지했다.
- 기존 꽂기·개요·자세히 보기·꺼내기 흐름, 슬롯 좌표 계산, `absolute/fixed` 구분, z-index `85/84/250`은 복제본 그대로다. 시안 전환 후 이전 핸들러가 개입하지 않도록 클릭 핸들러에 `active()` 가드 하나만 더했다.
- `prefers-reduced-motion`에서는 모든 CSS 자동 모션·전환을 끄고, 기존 JS 동작대로 카드는 곧장 상세로 이동한다. **꽂기 검증은 `no-preference`로 따로 해야 한다.**
- 새 장식 문구는 JS에서 ko/en 쌍으로 정의했다. 글꼴은 기존 테마가 로드하는 Noto Sans KR을 재사용하고, Laureate만 variant `fonts`로 Noto Serif KR을 추가했다.
- 자작 월계관·별·기하 도형·권호·기존 사이트 고스트만 사용했다. 닌텐도·마리오·Wii·기념 로고 및 캐릭터 이미지는 구현에 포함하지 않았다.

## 4. 검증 기록과 재현

완료한 검사:

- 3개 JS + 등록 파일 문법 검사.
- Prettier의 CSS 파서로 3개 CSS 구문 분석.
- 등록 데이터의 ko/en·script 경로·미리보기 파일·stage ID 확인.
- 여섯 페이지의 기존 renderer를 ko/en으로 실행해 원본 데이터와 마크업 생성 확인.
- SVG 파싱·래스터 렌더 3개, 임시 구성도 렌더 3개. 렌더한 기기의 외곽선·면취 모서리·두께 면을 직접 열어 확인.
- 원본 대비 interaction 코드 보존, reduced-motion 처리, 흰 도구 로고판, 사진 규칙·스킨 선택자·카드 내부 미디어쿼리 정적 검사.
- `git diff --check` 및 변경 범위 검사. 상세 결과는 [static-checks.json](static-checks.json).

미완료: 실제 6페이지 × 모드 × 화면 크기의 가로 넘침·JS 런타임 오류·폰트 줄바꿈·꽂기·개요·버튼 동작. 실제 screenshot은 0건이다. `shots/`의 JSON을 통과 리포트로 해석하면 안 된다.

재현 명령(프로젝트 루트):

```sh
python3 -m http.server 8901
# 별도 터미널
node rnd/verify.cjs
```

`verify.cjs`는 1440×900, 1280×720, 390×844, 320×844의 한국어 144장과 좁은 화면의 영어 72장, 모드·오류·문서 폭을 기록한다. 홈에서 일반 모션으로 꽂기 → 개요 → 꺼내기 → 다시 꽂기 → 자세히 보기를 3개 폭에서 확인한다. 모션 최소화의 직접 상세 이동도 별도 검사한다. 성공적으로 실행하면 홈 1280×800 실제 캡처를 800×500 JPG로 줄여 임시 갤러리 이미지를 교체한다. 결과 이미지는 `rnd/shots/`에 모인다.

생성 스크립트:

```sh
python3 rnd/finish-variants.py   # classic + rnd 템플릿 → 시안 CSS·JS
node rnd/export-art.cjs        # 실제 SVG 몸통 + 촬영 대기 구성도
python3 rnd/render-svg.py      # 시스템 librsvg/cairo로 임시 이미지 렌더

```

`finish-variants.py`는 반복 실행 가능하다. 시안 직접 편집 후 실행하면 템플릿 내용으로 다시 생성되므로, 후속 변경은 `rnd/system.css`, 각 방향 CSS, `rnd/art.js`에도 반영해야 한다.

## 알려진 한계와 다음 판단 기준

- **기념 선집**: 외부 웹폰트 로드 실패 시 세리프의 인상이 달라진다. 금박은 실제 재질이 아닌 CSS 색·선·정적 그라디언트 표현이다. 권호 01은 설명상 ‘첫 컬렉션’이며 경력 연수를 암시하지 않는다.
- **소장품 전시**: 제품 소개·전시관에 가까운 차분함이 강하다. 기존 제품 사진 안과의 차이는 큰 원형 장면·전시 번호·본문의 라벨 규칙에 두었다. 실제 전체 페이지 비교에서 차이가 충분한지는 사용자의 판단이 필요하다.
- **랠리 프린트**: 사선과 두꺼운 띠가 긴 본문에서도 강하게 느껴질 수 있다. 기울임꼴은 본문 전체가 아니라 제목·탭·정보 표제에 제한했다. CSS의 한글 합성 기울임은 브라우저별 차이가 있을 수 있다.
- 공통: 실제 화면 검증을 샌드박스 예외로 건너뛴 상태다. 장식된 SVG 연구 이미지로 실제 브라우저 품질을 보장하지 않는다.

배포 규칙 메모: 요청이 공용 파일 수정을 두 등록 파일로 제한하므로 `.assetsignore`는 변경하지 않았다. `/rnd`는 내부 조사·검증 자료이며 이번 작업에서는 푸시·배포하지 않는다. 통합·공개를 진행할 때 담당자가 `/rnd`의 배포 제외를 적용해야 한다.

# 실제 화면을 본 뒤의 2차 수정

사용자가 제공한 3개 시안의 실제 화면, 게임기 확대, 개별 모바일·하위 페이지 PNG를 직접 열어 검토했다. 자료는 [shots/user-round2](shots/user-round2)에 원본 그대로 보관했다.

## 판단과 변경

1. **진열판의 검은 굵은 선은 의도한 콘셉트가 적용되지 않은 부분이었다.** 원본의 `:root[data-skin] .fcs-rig .draw__stage`가 방향별 `[data-skin] .draw__stage`보다 구체적이라 배경·선·그림자를 덮었다. 방향별 규칙을 같은 구체성으로 바꾸었다. 선집은 깊은 진홍 판과 금색 이중선, 전시는 밝은 전시대와 녹회색 두께, 랠리는 노란 판과 빨간 상단 띠를 사용한다. 카드 내부 칸은 그대로다.
2. **화면 크기에 비해 프로필과 조작 요소가 작았다.** 데스크톱 사진 폭을 `16cqw → 19cqw`, 이름·직무·한마디·버튼 글자에는 최소 크기를 주었다. 버튼은 최소 높이 36px이다. 개요의 9~10px로 줄던 보조 정보도 10~12px 하한으로 조정했고, 원래의 스크롤 가능한 화면을 유지했다.
3. **이력서의 화면이 사진과 작은 스크롤 안내만 남아 비어 보였다.** 해당 페이지에만 기존 `meta.name`, `meta.role`의 ko/en 값을 추가한다. 새 직함·이력·성과는 만들지 않았다. 콘텐츠 렌더러와 슬롯 로직은 수정하지 않았다.
4. **전시 시안의 사진에 아치와 사각 외곽선이 동시에 보였다.** 원인은 `.hero__portrait`의 옛 픽셀 프레임이다. 세 시안의 불필요한 바깥 프레임을 없애고 각자의 `.portrait` 액자만 남겼다. 전시 시안은 아치 액자와 흰 바탕을 명시했다. 사진 필터·혼합·오버레이는 추가하지 않았다. 몸통의 녹회색 옆면과 액정 테 대비도 높여 배경 원에 묻히는 정도를 줄였다.
5. **모바일 버튼과 하단 링크의 가독성이 약했다.** 화면 버튼은 12px/최소 38px 높이로, 손잡이 키는 390px에서 36px, 320px에서 34px로 늘렸다. 버튼 두 개는 폭이 제한된 2열에 넣고 긴 언어도 줄바꿈할 수 있게 했다. 장식 설명은 9px에서 11px로 키웠다. 밝은 푸터에서 흰색으로 남던 이메일/GitHub 링크를 본문 색과 테마 호버색으로 수정했다. 진홍 바탕의 고스트 자리표시자도 금색으로 읽히도록 했다.

게임기 SVG 실루엣, 손잡이·화면 위치, `.fcs-rig` 원근, 카트리지 cqw 칸, 슬롯 계산·z-index·꽂기 흐름은 바꾸지 않았다. `rnd` 템플릿과 생성된 시안 CSS·JS를 함께 갱신했다. 공용 등록 파일에는 추가 변경이 없다.

## 검증의 범위

- **수정 전 사용자 실측:** 세 시안 × 여섯 페이지 × 라이트/다크 × 1440/390/320px에서 콘솔 오류 0, 가로 넘침 0, 꽂기 → 개요 정상. 제공된 `report.json`과 사용자의 설명에 근거한다.
- **수정 후 직접 수행:** JS·CSS 구문, 등록 정보, 카드 고정 칸·사진 규칙·스킨 범위, 원본 인터랙션 코드 보존 검사 통과. 기존 렌더러도 여섯 페이지 × ko/en 생성 통과. `git diff --check` 통과.
- **수정 후 실제 브라우저:** `node rnd/verify.cjs`를 다시 실행했지만 Chromium 시작이 샌드박스에서 차단되어 0장이다. 사용자 실측을 수정 후 통과 결과로 재사용하지 않았다.
- SVG 몸통·표시된 임시 구성도·흑백 비교를 다시 생성했다. 갤러리 JPG는 계속 촬영 대기 구성도이며, 제공된 수정 전 스크린샷을 수정 후 화면으로 바꿔 넣지 않았다.

추가 촬영에서 우선 확인할 곳은 320px 영어 화면 버튼, 900~1100px의 화면 세로 여유, 읽기 크기를 높인 개요의 스크롤, 세 진열판의 실제 색·외곽선이다. 기존 [verify.cjs](verify.cjs)로 같은 화면 행렬을 촬영할 수 있다. 커밋·푸시·배포는 하지 않았다.
